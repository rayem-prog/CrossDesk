# CrossDesk：Mac / Windows 双向图片剪贴板设计

状态：用户已于 2026-10-20 确认实施。

## 目标与使用方式

在现有 CrossDesk 连接中双向同步图片：

1. Windows 截图或“复制图片”，在 Mac 的聊天、文档、图片编辑器中直接粘贴。
2. Mac 截图或“复制图片”，在 Windows 的对应应用中直接粘贴。
3. 在 Finder 或资源管理器中复制一个或多个 PNG / JPG / JPEG 文件，在另一端文件夹粘贴，保留文件内容与文件名。单张图片文件也提供图片剪贴板表示，供支持该表示的聊天或编辑软件粘贴。

截图采用系统正常的“复制到剪贴板”操作。截图仅保存到磁盘、但未复制，不触发传输。两端处于已配对连接时自动同步，无需额外发送按钮。

本次不增加跨屏文件拖放、目录传输、任意文件或文本同步。已有显式开启的旧剪贴板模式不属于本次功能的启用方式。

## 方案比较与选择

1. **扩展现有加密通道的图片同步（推荐）**：保持一条连接，新增分块协议、图片格式统一与回传抑制，符合现有操作方式。
2. **直接恢复上游全部剪贴板模式**：实现较少，但同时开启文本、任意文件，且无法解决当前帧大小限制及会话生命周期问题。
3. **另建图片传输服务**：可以隔离传输，但增加端口、配对、启动和部署负担。

采用方案 1。

## 启用与兼容性

- 图片同步默认启用；两端命令增加 `--image-clipboard on|off`，允许显式关闭。
- 本次不默认启用普通文本或其他文件同步。
- 通信协议升级为 v5，在 Hello 中声明图片同步能力；只有双方均启用时才发送图片。
- v4 与 v5 在握手阶段清晰提示版本不匹配，两端需要同时更新。配对密钥格式、端口和键鼠跨屏使用方式保持兼容。
- 连接建立时仅记录当前剪贴板基线，之后的新复制操作才自动发送；断线期间旧剪贴板不在重连时自动补发。

## 数据流与组件

### 原生剪贴板适配

- Windows：优先识别文件列表，再识别 PNG / DIB 等图片表示；避免图片附带的文字或网页 URL 抢占图片内容。写入图片时发布 PNG 与 DIB；写入图片文件时发布 CF_HDROP，单图同时提供图片表示。
- macOS：读取 NSPasteboard 的文件 URL、PNG / TIFF / JPEG 等图片表示；文件列表读取使用明确的标准输出协议。写入图片时发布有效的 PNG / TIFF；写入文件时发布文件 URL，单图同时提供 PNG 表示。
- 原生格式与图片转换在平台适配层完成，传输层不依赖系统剪贴板。
- 位图统一为 PNG 传输，保留透明度；文件复制保留原始 PNG / JPG / JPEG 文件字节。

### 共用图片会话模块

- 共用模块负责图片筛选、快照指纹、传输收发、临时缓存与线程停止，供 Mac 客户端和 Windows 服务端调用。
- 每个会话最多一个剪贴板观察线程。收到断线或本地停止信号后结束并回收线程，避免重连后重复观察、向旧连接发送。
- 本地观察、远端写入及写入后的原生快照在共用同步边界协调。以规范化像素内容 / 文件内容指纹识别远端写回，不采用“短时间内忽略任意同类图片”的规则，避免漏掉用户接着复制的另一张图片。
- 已成功发送的快照才标记为已发送。新的复制替代未开始发送的旧快照，传输失败不改变对端现有剪贴板。

### 加密分块传输

- 新增图片传输开始、数据块、完成三类帧，包含会话内唯一传输 ID、内容类型、文件名、长度与摘要。
- 数据块为 16 KiB，现有单帧 64 KiB 限制保持不变；数据块之间允许键鼠事件及心跳优先发送。
- 接收端验证传输 ID、顺序、声明长度、文件个数与摘要。完成整组且所有图片有效后，才一次性发布到系统剪贴板。
- 两端都能同时发起一组传输，接收状态按方向隔离。
- 用户在接收期间已经产生更新的本地复制时，完成的旧远端传输不得覆盖更新的本地剪贴板；记录跳过原因并正常保留键鼠连接。

## 范围、限制与错误处理

- 单个文件或 PNG 传输内容最大 32 MiB；一组最大 128 MiB、最多 32 张。
- 解码后的图片最多 32 Mi 像素，解码分配上限 128 MiB；在写入剪贴板前检查图片格式与尺寸。
- 文件复制仅接受真实普通文件，扩展名为 PNG / JPG / JPEG 且内容可解码。混合图片与其他文件、目录、符号链接等不自动传输，并给出明确日志。
- 远端文件名必须为安全的单个文件名，拒绝目录穿越及绝对路径；同组同名文件确定性添加序号，避免覆盖。
- 接收内容写入应用自己的唯一临时目录，不覆盖用户目标目录；用户正常粘贴时由 Finder / 资源管理器决定落盘位置。
- 中途断开、长度不符、摘要不符、无效图片、资源上限或乱序帧均不发布不完整剪贴板；清理未完成缓存，保留当前有效剪贴板。
- 接收完成的缓存不能在下一组到来时直接删除仍可能被剪贴板引用的文件；按缓存生命周期清理，不破坏当前文件复制。
- 剪贴板被其他应用短暂占用时有限重试；超限或无效的本地内容只跳过该复制，不能因此关闭键鼠连接。
- 日志记录方向、图片数、字节数、完成或跳过原因，不记录图片内容或配对密钥。

## 验证与交付

先为以下真实行为补充失败测试，再实现对应变更：

1. 超过 64 KiB 的 PNG 和多图文件分块完成传输，重组后内容一致。
2. PNG 透明像素不丢失；PNG 与原生图片重编码不会触发循环回传。
3. PNG / JPG 文件内容、中文文件名与多图顺序正确；拒绝混合选择、越界路径、超限、截断及错误摘要。
4. 远端写回不回传，但用户紧接着复制另一张图仍能发送。
5. 接收期间新的本地复制不被过时的远端结果覆盖。
6. 断线后观察线程退出，重连后不会累计重复线程；中途失败不会发布不完整剪贴板。
7. 大图传输期间键鼠帧与心跳仍能穿插，双方同时发送不混包。
8. v5 能力协商、明确的 v4 拒绝、图片关闭开关及已有键鼠行为回归。

运行 Mac 原生 Rust 测试、格式检查、release 构建；验证 Windows 目标编译并保留 Windows 原生 CI 检查。平台剪贴板交互测试使用隔离剪贴板或显式手动验收，避免自动覆盖用户日常剪贴板。

交付修改后的代码、Mac 可执行构建及双机验收步骤。Windows 原生运行、聊天软件兼容性和双机真实复制粘贴，仅在有对应设备验证结果后标为通过；不能以 Mac 单元测试代替 Windows 实机验证。
