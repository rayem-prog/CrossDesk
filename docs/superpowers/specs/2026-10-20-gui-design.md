# CrossDesk 0.4.0 图形界面设计草案

> 已由 [2026-10-21 便捷开启传输设计](2026-10-21-easy-connect-design.md) 取代；以自动发现、首次短码配对、记住设备和打开即连接为本次目标。

状态：用户已选择“图形界面：连接状态、设置和操作按钮”为下一功能；本文件和配套实施计划供确认，尚未实施。

## 目标与可见行为

打开 CrossDesk.app 或 Windows 程序即可进入界面。Windows 显示“启动监听”，Mac 显示“连接 Windows”。应用启动时不自动连接。

1. 首页区分未启动、启动中、等待连接、连接中、已连接、重试中、停止中、失败。已连接只能由通过配对认证、协议校验和本地初始化的子进程确认，不能由进程存活推断。
2. Mac 设置 Windows 地址，默认端口 24920；Windows 设置监听地址和左右进入边界。第一版接受 IP:端口，输入单独 IPv4 时补上 :24920；IPv6 使用 [地址]:端口。
3. 选择现有 crossdesk.key，或在 Windows 通过保存对话框生成新配对文件。界面仅展示路径和校验结果，提醒两端使用同一文件；已存在的文件不能被生成操作覆盖。
4. 图片同步、普通文件同步各有独立开关；保存后传给真实服务进程。运行期间锁定这些连接设置，提示停止后修改。
5. 启动、停止、重新连接、清空日志按钮，以及最多 500 行日志。断开会停止本地服务和当前传输；重新连接会停止旧子进程再启动一个新进程。
6. 关于页显示 CrossDesk 版本和 rayem-prog/CrossDesk 地址；保留 Deskbridge 来源说明。尚无本项目 GitHub Release 时显示“尚无发布版本”，不报“已经是最新版”，也不跳转上游下载。

## 路线比较

| 路线 | 收益 | 成本与取舍 |
|---|---|---|
| 复用现有 Tauri 2 / React 界面（推荐） | 已有启动、日志、配置基础；两端共用界面 | 需要接上真实连接状态、配对设置，修复旧名称和 GUI 打包 |
| 分别编写 macOS / Windows 原生界面 | 可以更深地贴合系统操作 | 两套界面和测试，首版交付工作量明显增加 |
| 仅提供本地网页控制台 | 易预览和调整 | 增加本地 HTTP 服务、端口和生命周期管理；当前项目已有桌面基础 |

采用第一条路线。界面仍控制独立服务子进程，继续使用已验证的键鼠、图片和文件核心。

## 全局约束

- 目标版本 0.4.0；网络协议保持 v6，TCP24920，继续使用已有配对密钥。
- Windows 仍为键鼠服务端，Apple Silicon Mac 仍为客户端；剪贴板双向传输。
- 文件限制保持 512 MiB/文件、2 GiB/批次、64 文件、4 GiB 缓存；图片限制保持现状。
- 不新增网络监听端口，不把服务进程存活显示为已连接。
- GUI 专用通信只使用父子进程管道；结构化状态从 stdout 读取，普通诊断从 stderr 读取。
- GUI 不展示密钥内容；不把密钥放进日志、配置内容、源码或交付包。
- GUI 配置保存在 CrossDesk 的用户配置目录；明确的用户自定义配置路径优先，旧配置只读取迁移，不删除。
- 无参数 GUI 构建打开窗口；无参数无 GUI 构建继续显示帮助；server/client/keygen/--help/--version 命令保留。
- GUI 启动不自动连接；停止、重新连接和退出不能留下旧服务子进程。
- 自动化测试不连接用户的真实设备，不修改日常系统剪贴板。
- 不在本次范围内加入文件夹、断点续传、开机自启、托盘后台常驻、文本同步或传输百分比。

## 结构与数据流

配置进入 Rust 后校验角色、地址、开关和配对文件，再通过 Command 的独立参数传给服务，不拼接 shell 命令。GUI 用 Tauri 的原生文件对话框选文件；文件读取和密钥解析由 Rust 执行。

服务在 stdout 输出前缀为 `crossdesk-event\t` 的单行 JSON。状态类型有固定枚举；stderr 中即使出现相同文字，也不能被当作状态。GUI 父进程记录最新状态并提供 get_state；前端沿用轮询，但每次请求结束后才安排下一次，避免请求堆积和覆盖正在编辑的表单。

父进程停止时通过 stdin 发送 stop。每个子进程只安装一个控制读取器；EOF 同样触发退出。当前会话的 socket 注册到退出管理器，停止能中断读等待并让工作线程清理。父进程等待两秒后仍未退出才终止并回收子进程，界面明确记录强制终止。重连必须等旧子进程回收后再启动。

Tauri 命令中的文件、子进程和网络工作在阻塞工作线程执行。窗口关闭或应用退出时执行同一停止路径；第一版关闭窗口即退出。

## 已发现的接入缺口

- src/control.rs 的 is_running 仅检查子进程；当前没有认证后的连接状态。
- ServiceLaunch 没有 --key-file、--image-clipboard、--file-clipboard 参数。
- src/shutdown.rs 的 stdin 观察器只读取一行，且在客户端每次会话中创建；需要提升到子进程生命周期。
- src/gui.rs 和 web/src/main.jsx 中的更新和项目链接仍为 paulhe666/deskbridge。
- tauri.conf.json / web/package.json 仍显示 Deskbridge 1.6.9；GUI 当前不是默认构建。
- 旧 GUI 打包脚本未启用 gui feature，Windows 还寻找 deskbridge.exe；现有 headless CI 不能证明 GUI 包可用。
- 当前配置会尝试程序目录；已安装的 .app 内应改用用户目录，避免修改包内容。

## 验收

自动化覆盖配置往返、启动参数、状态管道、启动/停止/重连/异常退出、前端按钮状态与错误显示。Mac 与 Windows 原生 CI 分别测试并构建 GUI 包，保留无 GUI 流水线和 129 MiB 传输验收。

真实双机验收：从 GUI 选择同一密钥，连接成功后图片和 PDF 双向实际粘贴；关掉文件同步后不再传普通文件；错误 IP、错误密钥、缺权限均有可见反馈；停止立即释放控制；连续重连十次后仅一个服务子进程，关闭应用后无残留。未完成的物理验收必须保留为待验收状态。
